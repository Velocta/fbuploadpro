# Design-system enforcement baseline (spec 129 §5.4 / PR-F2, T14).
#
# WHY THIS FILE EXISTS: the literal bans (hex / rgb() / hsl() colour literals,
# raw px font-sizes, ad-hoc numeric z-index, !important outside the globals
# overrides layer) are the end state, but the pre-rebuild tree already
# contains legacy occurrences in surfaces that PR-F2 does not own. This file
# FREEZES them per file and per category: the regression guardrails
# (.github/scripts/regression-guardrails.sh, checks 9-12) FAIL when
#   - any listed count INCREASES,
#   - a file not listed here gains an occurrence,
#   - a listed count DECREASES without this file being updated in the same PR
#     (counts only ever go down, as specs 130-136 convert each surface).
# New code must use design tokens / token-backed Tailwind utilities instead.
#
# Exempt by design (not scanned): apps/web/tokens/** (the token source),
# apps/web/src/styles/tokens.generated.css and apps/web/src/lib/theme.ts
# (generated outputs — tokens:check guards them).
#
# Categories: hex | rgb | fontsize | zindex | important
# Format: <category> <path-relative-to-repo-root> <count>
#
# The `important` lines double as the !important ALLOWLIST: every entry is a
# legacy block evicted verbatim from globals.css into its owning component
# (spec 129 T12 — button/checkbox/input/select/sidebar/skeleton/switch/
# textarea). (The pre-existing style block in auth-split-layout.tsx was
# deleted by spec 136 PR-136A; its hex/rgb/important lines left this file
# with it.) In globals.css itself, !important is permitted ONLY
# inside @layer overrides (position-checked by the guardrail; count 0 today).
#
# Tailwind arbitrary-value allowlist (spec 129 §5.4): bracket-form utility
# values (text-[13px], bg-[#fad734], z-[9999], ...) and important-modifier
# classes are BANNED in apps/web/src. An exception needs a line here:
#   arbitrary-allow <path> <exact-class-token>   # plus a reason in the PR
# Exceptions (ONE, named): the four `transition-[...]` property-list classes
# in components/shared/ui/sidebar.tsx come verbatim from the upstream shadcn
# sidebar (PR-F3 rebuilds that same sidebar, per Shahzeb's directive): they
# name CSS properties only and carry NO design value (durations/easing are
# the duration-base / ease-standard tokens). Accepted as a named baseline
# exception at the #658 merge (Shahzeb-approved, gate-recommended);
# zero behaviour change.
