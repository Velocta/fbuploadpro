# Feature Specification: First Comment Scope Alignment (pages_manage_engagement)

**Feature Branch**: `feat/044-first-comment-scope-alignment`  
**Created**: 2026-10-15  
**Status**: Draft  
**Input**: User request: "yes" to adding `pages_manage_engagement` to OAuth scopes and BYOC settings for the first comment feature  

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Authorized First Comment Publishing via OAuth Alignment (Priority: P1)

As a content creator or social media manager,  
I want my connected Facebook Pages to have full authorization to post automated first comments on newly published posts and reels,  
So that promotional links, credits, and calls-to-action are reliably posted in the first comment without permission errors from Meta Graph API.

**Why this priority**: Without the `pages_manage_engagement` scope, Meta Graph API v26.0 rejects `POST /{post-id}/comments` calls with `(#200) Requires pages_manage_engagement permission to manage the object`, causing automated first comments to silently fail in production.

**Independent Test**: Connect a Facebook account via OAuth and verify that the authorization URL requests `pages_manage_engagement` alongside `pages_show_list,pages_read_engagement,pages_manage_posts,business_management`.

**Acceptance Scenarios**:

1. **Given** an authenticated workspace user initiates the Facebook connection flow at `/api/auth/facebook`,  
   **When** the user is redirected to Meta's OAuth dialog,  
   **Then** the `scope` query parameter contains `pages_manage_engagement` as part of the permission set: `pages_show_list,pages_read_engagement,pages_manage_posts,pages_manage_engagement,business_management`.

2. **Given** a user connects via the 15-minute magic link at `/connect/facebook?token=...`,  
   **When** the OAuth redirection URL is constructed,  
   **Then** the `scope` parameter includes `pages_manage_engagement`.

3. **Given** a scheduled queue item with a non-empty `first_comment` is published to a Facebook Page,  
   **When** the publishing worker executes `POST /{post-id}/comments` with the acquired Page token,  
   **Then** the request is successfully authorized and returns a valid `commentId` without permission errors.

---

### User Story 2 - BYOC Setup Guidance & Permissions Transparency (Priority: P2)

As a workspace administrator configuring a custom Meta App (BYOC),  
I want the BYOC setup view to clearly display `pages_manage_engagement` in the Required Meta App Permissions checklist,  
So that I configure the correct permissions in my Meta Developer Dashboard during app setup.

**Why this priority**: Workspace owners running their own Meta Apps need clear, non-technical instructions and badge lists matching the exact permissions the application requests at runtime.

**Independent Test**: Visit `/tenant/[subdomain]/settings?tab=byoc` and verify that `pages_manage_engagement` is rendered in the permissions badge list.

**Acceptance Scenarios**:

1. **Given** a user is on the BYOC Facebook App settings tab,  
   **When** viewing the "Required Meta App Permissions" section,  
   **Then** `pages_manage_engagement` is displayed as an unboxed theme-compliant badge alongside `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`, and `business_management`.

---

## Edge Cases

- **Existing Connected Accounts**: Accounts connected prior to this update may not have granted `pages_manage_engagement`. When publishing a post with a first comment, the main post must still succeed and the failure of the comment must be non-fatal to the post itself, warning the user that re-authentication is required.
- **Story Post Format**: In accordance with platform invariants, `story` format posts strictly prohibit and suppress first comments (`first_comment = NULL`). The presence of `pages_manage_engagement` must not cause any comments to be sent for stories.

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST include `pages_manage_engagement` in the OAuth scope string in `/api/auth/facebook`.
- **FR-002**: System MUST include `pages_manage_engagement` in the OAuth scope string in `/connect/facebook`.
- **FR-003**: System MUST surface `pages_manage_engagement` in the BYOC settings view under Required Meta App Permissions.
- **FR-004**: System MUST ensure automated tests for Facebook OAuth initiation validate the presence of `pages_manage_engagement`.
- **FR-005**: System MUST document the role of `pages_manage_engagement` in `docs/foundational-knowledge.md`.

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of Facebook OAuth authorization URLs generated by the web application include `pages_manage_engagement` in the query parameters.
- **SC-002**: 0 regression failures in existing authentication, publishing, and BYOC test suites.
- **SC-003**: Automated first comments on published posts and reels execute with valid authorization under Meta Graph API v26.0.

---

## Assumptions

- Meta Graph API v26.0 continues to enforce `pages_manage_engagement` as the required scope for `POST /{post-id}/comments`.
- `public_profile` continues to be granted implicitly by Meta and does not require explicit enumeration in the scope parameter.
- `pages_manage_metadata` and `read_insights` remain unnecessary for FBUploadPro's publishing and insights workflows.
